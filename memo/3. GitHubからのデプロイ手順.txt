
==========================================
GitHubからWebサイトを公開する手順
==========================================

GitHubはソースコードを保存する場所です。
GitHub Pagesを使うと、HTML・CSS・JavaScriptで作られた静的サイトを公開できます。

------------------------------------------
この方法が使えるか、ひと目で確認
------------------------------------------

○ 使える
- ポートフォリオ、会社案内、作品紹介など、ページを表示するサイト
- ブラウザー上で動くReactの操作（メニュー、入力フォームなど）
- 外部サービスや、別の場所に公開したAPIとの通信
- Next.jsのうち、静的ファイルとして書き出せる機能

× GitHub Pagesだけでは使えない
- Node.jsなどのバックエンドをGitHub Pages上で動かす
- サーバーで毎回ページを作るSSRや、実行時に動くAPI
- Next.jsのServer Actionsなど、サーバーでの実行が必要な機能

バックエンドやサーバー機能が必要な場合も、フロントエンドをGitHub Pagesに
公開することはできます。その場合はバックエンドを別のホスティングサービスに
公開し、フロントエンドからそのAPIへ接続します。

------------------------------------------
1. このプロジェクトをGitHub Pagesで公開する
------------------------------------------

このプロジェクトはViteで作られており、gh-pagesを使って公開します。

【必要なインストール】

初回だけ、プロジェクトのルートフォルダで依存パッケージをインストールします。

npm install

gh-pagesがまだ入っていない別のプロジェクトでは、次のコマンドで追加します。

npm install --save-dev gh-pages

このプロジェクトでは、gh-pagesはすでにpackage.jsonに登録されています。

【設定するファイル】

1. vite.config.ts

GitHub PagesのURLが
https://ユーザー名.github.io/リポジトリ名/
の場合、baseにリポジトリ名を設定します。

export default defineConfig({
  base: "/リポジトリ名/",
  // pluginsなど
})

ユーザー名.github.ioという名前のリポジトリや独自ドメインの場合は、
通常baseを"/"にします。

2. package.json

buildとdeployのコマンドを設定します。
このプロジェクトではすでに設定されています。

"predeploy": "npm run build",
"deploy": "gh-pages -d dist"

predeployはdeployの前に自動で実行され、サイトをdistフォルダに作ります。
deployはdistの中身をgh-pagesブランチへ公開します。

【公開手順】

1. GitHubにリポジトリを作り、ソースコードをpushする。

git add .
git commit -m "サイトを更新"
git push origin main

2. GitHubのリポジトリで「Settings」→「Pages」を開く。
3. Sourceを「Deploy from a branch」にする。
4. Branchで「gh-pages」、フォルダで「/ (root)」を選び、保存する。
5. プロジェクトのルートで次を実行する。

npm run deploy

6. GitHubの「Actions」で公開処理の完了を確認し、Pagesに表示されたURLを開く。

サイトを更新するときは、変更をmainへpushした後、再度npm run deployを実行します。

------------------------------------------
2. Next.jsのプロジェクトの場合
------------------------------------------

GitHubをソースコードの保存先として使う手順は同じです。
GitHub Pagesを使う場合は、Next.jsの機能を静的ファイルとして書き出せるか確認します。

Next.jsを静的サイトとして公開する場合は、next.config.jsなどに設定します。

const nextConfig = {
  output: "export",
};

npm run buildを実行すると、公開用の静的ファイルがoutフォルダに作られます。
GitHub Pagesへ公開する設定では、Vite用のvite.config.tsやdistではなく、
Next.js用の設定とoutフォルダを使います。

SSR、動的なAPI、Server Actionsなどを使う場合は静的ファイルだけでは動かせません。
VercelなどNext.jsのサーバー機能に対応したサービスへGitHubリポジトリを接続して公開します。

------------------------------------------
3. バックエンドAPIと連携する場合
------------------------------------------

GitHub Pagesはフロントエンドの静的ファイルを公開する場所です。
バックエンドやAPIを実行するサーバーは公開できないため、別のサーバーにデプロイします。

1. バックエンドAPIを、サーバー処理に対応したホスティングサービスへ公開する。
2. フロントエンドから、そのAPIの公開URLへリクエストを送る。
3. API側で、公開したフロントエンドのURLからの通信を許可する（CORS設定）。
4. APIの秘密鍵などはバックエンド側で管理し、フロントエンドへ埋め込まない。

フロントエンドとバックエンドのソースコードをGitHubに置くことはできますが、
GitHub Pagesで実行できるのはフロントエンドの静的ファイルだけです。
バックエンドは別のホスティングサービスで実行します。

------------------------------------------
注意
------------------------------------------

ViteのVITE_で始まる環境変数は、ビルド後にブラウザーから見える値になります。
公開してはいけない秘密情報は設定しないでください。
ホスティングサービスでビルドする場合は、そのサービスの環境変数設定を使います。
